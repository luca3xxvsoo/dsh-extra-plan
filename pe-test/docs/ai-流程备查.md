# 完整流程（主会话到验收的现行顺序）

> 本文件是交接流程唯一详版；机制不变量见 [ai-机制设计](ai-机制设计.md)，修改纪律见 [ai-维护手册](ai-维护手册.md)，实机顺序见 [ai-实机闸门测试流程](ai-实机闸门测试流程.md)。固定顺序不能因任务简单而跳过必要锚点。

## ① 进入预设

用户以“按需规划模式”进入会话。主会话先读入口导航与任务相关文档；AI 不默认加载历史归档。

## ② 展示时序

A=anchoredBootstrap、C=creativeMode、M=`native|ptc`；F 是会话尚无 `tool/call`，首个工具调用后为 L。A=1/F/main-planner 的 PTC 形态顶层只保留 `run_code` 与两段引导/read 文案，native 为 HN、ptc 为 HP；C=0 只改变模型可见面，不改变 runtime binding、deny 或 `tools/pre-execute`。

PTC C=0/C=1 必须各用干净 A=1 顶层会话取 F→首个 tool/call→L→第二调用；native HN 与 ptc HP 分别取证。历史会话只能提供 L，不能证明 F。

## ③ 接收需求

用户提出任务后，主会话记录目标、范围和限制；不在未确认路由前执行工作区写入。

## ④ 只读探查

先用 `read`/`glob`/`grep`/`web_search` 或只读 shell 理解任务；定位代码优先读 [ai-代码地图](ai-代码地图.md)。路由前 ordinary 探查和 ordinary 澄清 ask 可用，不应误拦。

## ⑤ 探查方式二选一

复杂度评估后必须用 `ask_user_question` 二选一：**主会话探查** / **探查者探查**，推荐项排第一，用户选择决定路径。并行收益、上下文隔离收益、方向侦察收益只用于形成推荐，不自动替用户决策。

- 主会话探查：主会话自己只读查证。
- 探查者探查：主会话用 `subagent_probe` 委派探查者；探查者只读、可 `save_probe` 落盘证据，回主会话只给“路径 + 2-3 行摘要”。
- 探查者只由主会话委派；规划子代理、执行者、验收者不得递归委派探查者。规划子代理有缺口时输出“申请继续探查：<待查项> — <原因>”，交回主会话。
- **根与冻结来源随交接携带**：每次探查、规划、执行和验收交接都记录 W、H（如有）、用途、根来源、文件身份与冻结 SHA；W 取 `session.header.cwd`，H 只接受可信 Host context/精确文件能力或显式验证根。缺根、非法/冲突根、Other 或无法证明的链接立即 BLOCKED/NOT-RUN，不默认扫用户目录、不用普通文件 `dirname` 升级授权；只读探查也只能落在声明的合法范围。`persona`、角色职责、机械选项、四版本声明和原有顺序不因双根隔离改变，隔离 fixture/静态证据不冒充实机。

## ⑥ 复杂度与推荐路由

根据对象数量、改动规模和信息完整度推荐：简单明确可直行，复杂/多文件/需要方案走 pro 规划，需求不明确先澄清。推荐不是自动决策，仍须用户确认。

## ⑦ 路由确认

主会话按现场 `config.gateWords` 发一次两问 ask：第一问是三选一路由词，第二问是纯文本“补充要求”（可留空、不得带 options）。固定顺序为 **route → purpose → 普通澄清**；重新开始流程仍需重新路由。

- 直行词：主会话按用户要求执行；执行类委派仍只认批准锚点。
- 规划词：进入 ⑧-⑫。
- 否决词、空白或取消：不动作；拒绝不清阶段状态，用户取消/中断清 `route/purpose/clarified/approved`，通道级故障只保留 `channelBroken` 逃生。
- `send_message` 仅 main 用于续轮转达，不替代 route/purpose/approved，不产生或清除人类批准窗；child 不得直呼或在 `run_code` 中调用。新 user/message 会切断旧事件窗。main 向 running 子代理发 send_message 被拒（文案『子代理running中，禁止打扰』）；目标 idle/非 running 放行，main 可续轮。child 的阻塞疑问不走 send，而以最终回复返回。
- `interrupt_agent` 仅 main 保留；main 仍须任务/用户授权且目标属于调用者自己的后代，不得干预父/兄弟或任意目标。`isSubagentChild` 对 child 直呼与 `run_code` 成员统一硬拒；自动最终结果不受影响。真实消息/中断留 HUMAN/NOT-RUN，当前验证状态看[ai-宿主耦合台账](ai-宿主耦合台账.md)。

## ⑧ 目的与澄清

规划词答复后，**第一个** ask 必须是独立的目的 ask，恰好一问，选项只取当前 `purposeRefine/purposeRedo`。目的答复后，再独立发 1-3 个关键澄清问题；澄清选项不得包含当前目的词的子串。

只有 route=plan、目的已定且澄清答复完成，才置 `clarified=true`，随后才允许 `save_probe` 与 `subagent_plan`。route 重选清 purpose/clarified/approved，有效目的重选清 clarified/approved。

## ⑨ 线索落盘

主会话或已认领探查者用 `save_probe` 写入 `.extra-plan/` 单个线索文件；四类定位信息为 fileMap/focusAreas/exclusions/background，证据限制和路径校验以 `save-contract.js` 为唯一真源。主会话侧 `save_plan` 是受限规划工件；不要把历史 evidence 数当作当前限制值。

## ⑩ 规划子代理

主会话用 `subagent_plan` 后台委派，prompt 自包含目标、范围、文件、用户目的和线索路径，并写明“先 read 线索，再按需补查”。规划预算由运行时计数；耗尽时走“申请继续探查”→主会话探查/委派→`save_probe`→由 main 以 `send_message` 转达→预算重置的往返（转达前提：planner 已停（非 running））。child 仅以最终回复返回，不提供控制工具。

规划产出格式固定为：

- **规划方案**：目标、步骤分解（每步做什么/涉及文件/关键命令）、风险与回滚；已探查核实步骤标【已探查核实】并带证据路径。
- **验收标准清单**：每条带任务编号、文件路径、期望值/行号/数值/文案与禁止项；路径、数字和文案照实写，不编造、不概括。

## ⑪ 回传、展示与批准

主会话用 `read` 读取方案和验收文件，核对任务、文件、修改内容与用户意图，再总结为“文件/修改内容/有无验收”表向用户展示，不要求原样全文展示，随后发批准 ask。批准 ask 仍为两问：第一问取当前批准/转规划/否决词，第二问是纯文本“修改意见”。批准词进入 ⑫，转规划词回到规划，否决词回到 ⑦。

## ⑫ 执行

创建执行者后台会话，执行者必须先读方案和验收文件，以文件内容为准，不重新规划整体方案；执行过程中逐条对照验收，发现问题立即修正。维护 dsh-extra-plan 项目时，执行者 prompt 必须显式携带“正式非归档文档只保留当前有效规则/状态/待验证项、历史先入现有归档、其他项目或非本项目工作不适用本条”的完整约束，不能只引用 READAI；维护其它项目时可忽略该项目专属规则，但不能忽略其它安全边界。执行者禁止委派递归、禁止写工作区外路径；任务如需越界，先完成工作区内部分，再汇报命令、目标路径、用途和预期内容，由主会话统一处理。

固定交付格式（≤15 行）：①完成清单（逐项动作与关键结果）；②自验证结论（逐项通过/不通过与一行证据）；③越界需求（如有）。仓库验收通过前 AI 不部署、不写 DSH_HOME、不改生产。

## ⑫-1 save_plan 派遣、取证与冻结

- 批准后的执行委派由主会话同时给出两份工件路径、领取的任务 ID、完整执行组、允许修改文件、组外依赖的交付证据、自检与回报要求；不要求复制整份正文，也不把工具 render 当作交接真源。维护 dsh-extra-plan 项目时，prompt、方案和验收工件必须显式携带项目专属当前态/历史归档约束及“其他项目不适用本条”的范围说明。一个执行者可领取多个独立组，同组任务不得拆派；独立组只有在依赖和资源满足时才可并行。`initialState` 只表示静态初始资格，不是运行状态。
- 直行路线仍受 route/approved 机械锚点约束；批准委派只在批准范围内执行。执行者不得重新规划整体方案、递归委派或越界写入。执行者自检只交付快速证据；需要写临时产物的执行取证，必须由已获授权的执行者或直行主会话运行并保留原始 stdout/stderr/退出码，reviewer 不被要求突破只读权限。
- 交接摘要必须把领取的任务、每个文件、文件操作和 `M` 点一起列出；修改前范围只是保存时源基线，不是验收坐标。验收按目标/锚点确认行漂移，证据记录实际新行号；任一源变化使受影响证据失效，需在冻结边界内重新取证。
- 四角色展示名的“按需规划模式-”前缀只用于显示，稳定 ID/order 独立使用；职责词可继续用 executor/planner/reviewer/prober 等短称，不必把职责段落全部替换成长名字。
- 每个执行者返回后即可为其对应组分配验收任务/检查 ID；全部数字任务与收尾完成后，主会话再做一次全局静态核对（git status 只列出方案声明路径、无跨组越界写、禁改面未动）并汇总各组结论。公共检查只指定一个领取者；同一验收组按检查定义顺序处理，资源和证据独立的不同验收组才可并行。

## ⑬ 验收

在仓库/工作区内验收，不把生产同步当验收动作。创建后台 `subagent_review` 时，除验收文件路径外还要给出领取的任务/检查 ID、各自期望与禁止、公共检查原始证据位置和冻结状态；维护 dsh-extra-plan 项目时，验收者 prompt 与验收工件必须显式携带完整项目专属当前态/历史归档约束及适用范围，不能只假定验收者读过入口。reviewer 只读验收文件、源文件和原始证据，逐项输出“通过/不通过 + 一行证据”，末行输出“验收通过”或“验收不通过：N 项问题”，全文不超过 20 行。main 再核对任务、检查、收尾和全局全覆盖；漏项、矛盾或源变化后的过期证据分别判为 INCOMPLETE/FAIL/需复验。验收不通过时主会话先判真伪，属实的用 send_message 把问题与证据原文返回该组执行者（每个执行者最多两轮），修复后重新派该组 reviewer 复验；两轮仍不通过记该组失败；组级成功/失败结论用于最终汇总。失败问题修正后按受影响任务、依赖消费者和共享检查重跑，最多两轮。

用户部署后才进行真实 DSH/QQBot 实测；静态 PASS、SKIP、HUMAN 不互相替代。

## ⑭ 地图维护与收口

所有扫描根内代码修改（`--roots` 默认 `plugins,pe-test/_shared` 的 .js/.mjs）完成后、最终冻结前，主会话从 W 运行 `node pe-test/tools/代码地图生成.mjs`，检查 stdout 的新增/删除/行号提示；只补人工意图/描述，不手改机器路径、函数、行号和同名顺序；再运行同前缀的 `--check`。地图生成与人工描述复核必须在最终冻结前完成；正式验收阶段只运行地图 `--check`，避免生成时间戳使冻结指纹漂移。纯文档或扫描根外文件改动不运行生成，验收仅 `--check`。修改来自执行者时也必须由主会话完成这一步。

固定仓库回归顺序：源码自检 → 当前文档/地图生成冻结 → 正式最终回归的 13 脚本矩阵与两项 check → 一键 runner 的 AUTO 14 项；纯 W 工具直接 `node`，需要 Host 代码的测试才显式采用 `DSH_INSTALL_ROOT=<本次真实代码根> node --import ./pe-test/_shared/host-preload.mjs`，代码根不授权数据 H。Markdown 不伪造 `node --check` 结果，SKIP/INCOMPLETE/HUMAN/NOT-RUN 不计 PASS；正式矩阵、两项 check 与 runner 的实际状态以当次冻结后的独立验收工件为准；未执行、部分执行和 HUMAN 必须分层保留，不得由局部自检替代整体验收。

## P2-2 执行口径

另开干净 PTC、C=0 顶层会话取 F；F 只核对插件手写 `tool:read`，L 连续两次保持输入不变并逐字对拍 `tools:sdk`。同一 Agent 的完整 L renderer 调用计数必须为 1，文本逐字相等；不跨 Agent/sessionId 复用，不以历史 textLength/textHits 代替证据。

## 设置与默认链交接

8 项 UI 设置与 2 项宿主行设置的权威值都走 `dsh-extra-plan-settings` 唯一 settings 行；PUT 只 edit 该行并保留其它字段，不再写旧公开 preset-sync 行。`./preset-sync` 与 locale exports 已退役，但 `lib/preset-sync.js` 仍由 settings owner 内部相对调用，raw patch 旧值继续迁移。`toolPresentationMode` 为装载期值，`runcodeCatchGate` 按配置热读。默认作者值来自 `agent.cordis.yml`，生成器产物不可手改；坏模板保持 last-known-good。
